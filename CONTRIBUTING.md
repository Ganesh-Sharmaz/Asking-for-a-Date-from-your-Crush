# Contributing

Thank you for helping improve this project. It is a small static website built with HTML, CSS, and JavaScript. Contributions should keep the project simple, accessible, safe, and easy to run in a browser.

## Before you start

Please search existing issues and pull requests first. For bugs, improvements, or new ideas, open an issue using the appropriate template before starting work. Wait for the issue to be acknowledged or assigned when the change is substantial. This helps avoid duplicate work and PRs that do not match the project's direction.

Small documentation fixes and clearly scoped typo fixes may be submitted directly, but they must still follow the pull request requirements below.

## What makes a good issue

Include a clear description, reproduction steps for bugs, expected and actual behavior, browser/device details when relevant, and screenshots or links when they help explain the problem. Do not include anyone's private phone number or personal information.

## Development

1. Fork the repository and create a focused branch from `main`.
2. Make the smallest change that solves the related issue.
3. Test `index.html` in a current desktop and mobile browser when relevant.
4. Check links, responsive behavior, console errors, and accessibility basics.
5. Update documentation when behavior or setup changes.
6. Open a pull request using the pull request template.

This project currently has no build step or automated test suite. Keep changes runnable by opening `index.html` in a browser. Do not commit secrets, personal phone numbers, tracking code, generated dependencies, or unrelated formatting changes.

## Pull request policy

Pull requests are welcome when they solve a documented problem or implement an agreed proposal. A PR may be closed without merging when it is missing the requested information, has no clear purpose, duplicates existing work, changes unrelated files, or introduces a breaking/design change without discussion.

Please explain what changed, why it changed, how it was tested, and include screenshots for visual changes. Maintainers may request revisions before review.
